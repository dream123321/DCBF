# DCBF Update - 2026-10-03

## 中文

- Reduce 的主要耗时瓶颈是多个 `.out` 描述符分片的文本解析和 descriptor store 构建。
- 新增内部块式解析路径：在不改变 descriptor 数值、帧顺序、原子顺序和筛选算法的前提下，只解析启用的 body，并使用连续 `float64` 描述符数组与 `int64` 结构索引。
- 多个较大的 `.out` 分片会使用受限的 `spawn` 解析进程并行处理，结果先写入紧凑二进制临时分片，再按原始分片顺序合并；小数据自动保持串行，避免进程启动开销。
- 不新增用户参数。解析并行度自动受 `encoding_cores`、当前作业可见 CPU 和内存预算共同限制。
- 修正 `reference_guided` 首次创建 checkpoint 时的状态序列化，续跑状态现在保存为可恢复的 selected-row manifest，不改变已完成 chunk 的选择顺序。
- `candidate_only`、`reference_guided`、断点续跑、预算、状态布居、逐维度最小覆盖和全局反向去冗余逻辑保持不变。10/3 版本只有在一致性、稳定性和速度测试通过后才适合替代旧版本。

## English

- The main Reduce bottleneck is parsing descriptor `.out` shards and building the descriptor store.
- The new internal block parser reads only enabled descriptor bodies into contiguous `float64` arrays with `int64` structure indices, while preserving descriptor values, frame order, atom order, and selection semantics.
- Larger sets of `.out` shards can be parsed by bounded `spawn` workers. Workers write compact binary shards, and the parent merges them in the original shard order. Small inputs stay serial to avoid process-startup overhead.
- No new user parameter is introduced. Parser parallelism is automatically limited by `encoding_cores`, visible job CPUs, and the available memory budget.
- Fixed checkpoint serialization during the initial `reference_guided` run so selected-row manifests can be restored; completed-chunk selection order is unchanged.
- `candidate_only`, `reference_guided`, checkpoint resume, budgets, state populations, per-dimension minimum cover, and global reverse pruning remain unchanged. This 10/3 build should replace the previous version only after consistency, stability, and speed tests pass.
